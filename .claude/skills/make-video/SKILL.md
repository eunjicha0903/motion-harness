# make-video

기준은 CLAUDE.md(고정된 것 · 게이트)와 `docs/`다. 이 스킬은 순서만 정한다.
영상 한 편의 파일은 모두 `out/<영상이름>/`에 둔다. 받은 레퍼런스 파일은 `references/`에만.

## 1. BRIEF (사람에게 묻기)

한 번에 묻고, 질문마다 기본값을 붙인다. "기본값"이라고 하면 그대로 정한다.

| 질문 | 기본값 |
|---|---|
| 무엇을 보여줄까? (화면 · 부품 · 한 줄 메시지) | `src/screens/` 중 요청에 가장 가까운 화면 하나 |
| 몇 초? | 15초 |
| 레퍼런스 ① 무엇? (링크 · 파일) | 없으면 motion.md 맨 위 출처의 레퍼런스 |
| 레퍼런스 ② 각각 무슨 역할? | 첫 번째 = 뼈대, 나머지 = 카메라 · 전환 · 글자 배치 중 하나씩 |
| 레퍼런스 ③ 꼭 닮아야 할 순간 하나는? (시점) | 뼈대 레퍼런스에서 움직임이 가장 큰 순간 |

영상이름을 짧은 영어로 정해 `out/<영상이름>/brief.md`에 적는다. 소리는 사람이 원할 때만 BRIEF에 넣는다.

## 2. 레퍼런스 정리 → `art-director`

`refs.md`가 나오면 빌릴 항목 표를 사람에게 짧게 보여주고 바로 다음으로 간다 (승인 아님).

## 3. 장면표 → `director` · **승인 1**

1. director가 3안 요약을 낸다. 사람에게 세 안을 보여주고 **하나를 고르게 한다** (추천 표시).
2. 고른 안으로 director가 장면표를 펼친다.
3. 장면표에 "새 후보"가 있으면 여기서 한꺼번에 묻는다. 승인된 값은 해당 docs에 먼저 적는다.

## 4. 스냅보드 → `builder` → `critic` · **승인 2**

1. builder가 스냅보드를 만든다.
2. critic이 판정한다. 사람에게 스냅보드를 먼저 보여주고 판정 한 줄을 붙인다.
3. 탈락이면 builder가 고치고 다시 critic. 같은 곳에서 2번 떨어지면 멈추고 묻는다.
4. 통과하면 사람에게 스냅보드 승인을 받는다.

## 5. 영상 → `builder` → `critic`

1. builder가 영상을 만든다 (`out/<영상이름>/video.mp4`).
2. critic이 판정한다. 영상을 먼저 보여주고 판정 한 줄.
3. 탈락 처리는 4단계와 같다.

## 끝

사람에게 알린다: 영상 위치 · 길이 · 판정 줄 · 이번에 docs에 추가된 새 후보(있으면).

## 참고할 곳 (내용은 베끼지 않는다)
- 움직임: motion.md 1–5장 · 영상 룩: video.md 1–5장 · 색 · 글자: design.md 1–3장 · 화면 · 부품 목록: design.md 6장
- 만드는 도구: `hyperframes` · `hyperframes-cli` 스킬
